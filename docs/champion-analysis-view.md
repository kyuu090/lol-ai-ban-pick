# チャンピオン分析画面

## 目的

StatsAPI の対面・タイムライン統計を、ドラフト進行中ではなく事前研究で参照できる画面として提供する。

## 画面への動線

1. メインナビゲーションから「チャンピオン」を開く。
2. Patch、Rank、Lane を選択する。
3. チャンピオン一覧の行を選択する。
4. チャンピオン詳細上部のアイコン付きタブで次の表示を切り替える。

- 「🛠 ビルド」: 既存のルーン、サモナースペル、アイテム、スキル情報
- 「↗ タイムライン分析」: 対面を限定しない5〜40分の平均推移
- 「⚔ マッチアップ分析」: 対面チャンピオン別の勝率一覧

タブは左詰めで配置し、選択中・ホバー・キーボードフォーカス中の背景表示でクリック可能な領域を示す。

ドラフト画面にはこの分析画面への導線を追加しない。

## 使用API

### マッチアップ分析

`GET /v1/stats/positions/{position}/champions/{championId}/matchups`

- APIの `baselineWinRate` は、一覧の「基準との差」を計算するために使用する。上部のサマリー表示は設けない。
- 各対面は試合数、対面勝率、`winRateVsOpponent - baselineWinRate` のポイント差を表示する。
- 対面チャンピオン、試合数、勝率、基準との差は列見出しをクリックして昇順・降順に並べ替えられる。
- 最小試合数は、制限なし、20、50、100試合から選べる。初期値は20試合。
- 対面行を選択すると、その対面の時間推移へ進む。

### 特定対面の時間推移

`GET /v1/stats/positions/{position}/champions/{championId}/matchups/{opponentChampionId}`

- チャンピオン概要に「VS」と対面チャンピオンのアイコン・名前を並べ、分析対象を常に確認できるようにする。
- Gold差、XP差、CS差、レーン戦収支の4グラフを同時に表示する。指標を切り替える操作は不要とする。
- Gold・XP・CSの各グラフでは差分を実線、リード率を破線で重ねて表示する。最終時点の値と試合数はカード上へ固定表示しない。
- Gold・XP・CSは左縦軸に差分、右縦軸にリード率を表示する。リード率は50%を基準に、3指標の実データ最大偏差へ余白を加えた共通の対称スケールを使い、数ポイントの変化と指標間の差を読めるようにする。
- リード率は差分と区別できる青い破線と点で表示し、50%の基準線を常に中央へ置く。
- グラフ内の横軸・縦軸の目盛りは、SVG の表示倍率とカード幅が異なるグラフ間でも、一覧表示のまま読み取れる約14px相当の統一された文字サイズで表示する。狭いレーン目標グラフは軸ラベル用の余白を確保する。
- レーン戦グラフは20分までに絞り、0を基準にしたレーン戦収支を棒グラフで表示する。正値は対象チャンピオン優勢、負値は対面チャンピオン優勢とする。各時点の棒は時間スロットの中央へ配置し、先頭・末尾を含めてグラフの描画領域内に収める。棒の値ラベルは、正値なら0より下、負値なら0より上の反対側へ表示する。
- TOP/MIDDLEは `isolated_kills_vs_lane - isolated_deaths_vs_lane` によるソロキル収支を使う。
- JUNGLEはガンクを含む全戦闘への寄与を評価するため、`(champion.avgKills + champion.avgAssists) - (opponent.avgKills + opponent.avgAssists)` による対象JGと相手JGのキル関与数差を使う。
- BOTTOM/UTILITYはAssistを加えると味方相方のDeathが含まれない分だけ正方向へ偏るため、duo laneの2v2基準で集計された `isolated_kills_vs_lane - isolated_deaths_vs_lane` を使う。
- 戦闘インパクトは、対チャンピオンダメージ、被ダメージ、敵へのCC時間を3つの小グラフに分け、対象を実線、対面を破線で同じ縮尺に重ねる。CC時間はミリ秒から秒へ変換して表示する。
- レーン目標は20分までを対象に、プレート取得・喪失の平均を左軸、アウタータワー取得・喪失率を右軸に重ねて表示する。
- 各時点の詳細値とその時点の試合数は、グラフの点または棒へのマウスホバーと同時に13.5px相当の独自ツールチップで表示する。遅延するSVG標準ツールチップは使用しない。
- 表形式の詳細値は初期状態では閉じ、必要な場合だけ「詳細データ（表）」をクリックして表示する。
- リード率と試合数の補足説明も詳細データ内へ収め、初期表示では主要グラフと開閉操作を優先する。
- 「対面一覧に戻る」で対面一覧へ戻る。

### 全体の時間推移

`GET /v1/stats/positions/{position}/champions/{championId}/timeline`

- 特定対面の時間推移と同じグラフ・表を使う。
- 重複するチャンピオン名、説明文、サマリーカードは置かず、主要グラフを画面上部に表示する。

## 情報密度の方針

- 主要指標はクリックによる切り替えを行わず、同一画面に並べる。
- Gold、XP、CS、レーン戦の4グラフはデスクトップ幅では2列×2行に大きく配置し、その下へ戦闘インパクトとレーン目標を2:1の横幅で追加する。カード上部は見出しと値を含まない凡例だけに絞り、時点別の値と試合数はツールチップへ集約する。
- 詳細値は時点ごとの縦長テーブルではなく、5〜40分を横軸にしたマトリクスへまとめ、初期状態では折りたたむ。
- 画面幅が狭い場合はグラフの最小幅を縮め、詳細マトリクスは横スクロールを許容する。

## フィルタと再取得

Patch、Rank、Lane は、チャンピオン一覧・ビルド・マッチアップ分析・タイムライン分析で共通に使用する。詳細画面を開いたままフィルタを変更した場合は、現在表示しているタブのAPIを同じ条件で再取得する。

ビルド画面の「対面チャンピオン」フィルタはビルドAPI専用であり、「マッチアップ分析」「タイムライン分析」では非表示にする。

## 表示上の注意

- 勝率には必ず試合数を併記する。
- 時点別の試合数は、その時点まで継続し、本人と対面の通常スナップショットが揃った試合数である。
- リード率は、対象チャンピオンの値が対面を上回った試合の割合である。
- TOP、MIDDLE、JUNGLE のレーン戦指標は1v1、BOTTOM、UTILITYはduo laneの2v2基準である。

## ユーザー試合のタイムライン表示

試合データ取得時は、1試合ごとに BFF から Match Detail を取得し、成功直後に対応する Timeline API を取得する。Timeline の生レスポンスはアプリケーションローカルへ保存しない。取得直後に DB の `match-detail-collector` と同じ 5 分刻み（5〜40分）のレーン対面集計へ変換し、画面表示用の集計済みポイントだけを `match-history` に保存する。

マッチアップ分析では対象チャンピオン・レーン・対面チャンピオンで、タイムライン分析では対象チャンピオン・レーンでユーザーのポイントを絞り込む。Gold / XP / CS では差分を実線、リード率を破線で表示する。キル収支、戦闘インパクト、プレート収支も線グラフで表示し、Stats API 全体値とユーザー平均を比較する。戦闘インパクトのユーザー系列は対象側のみ、レーン目標はプレート取得数から喪失数を引いたプレート収支のみを表示する。各時点はグラフ全高の透明なホバー帯で選択できる。色は緑（全体の対象側／取得）、赤（全体の対面側／喪失）、橙（ユーザーの対象側／取得）、水色（ユーザーの対面側／喪失）へ統一する。ユーザー試合のパッチ・ランク・キュー種別は Stats API のフィルタとは独立であり、ローカルに取得済みの Summoner's Rift 5v5 試合を母数にする。

## 実装箇所

- `ui/champions-view.ts`: URL生成、状態管理、API取得、分析表示
- `stats-db-api.ts`: Rendererから呼び出せるStatsAPIパスの許可
- `styles/stats.css`: 分析タブ、対面表、タイムライングラフ
- `styles/responsive.css`: 狭い画面での分析タブ・ヘッダー配置
- `test/ui-champions-view.test.js`: 分析API URL生成のテスト
- `test/stats-db-api.test.js`: 許可パスのテスト
